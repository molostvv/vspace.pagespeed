# Анализ ammina.optimizer на demis.ru и результат замены critical CSS

Дата: 2026-10-08. Источник — настройки в БД (таблица `am_optimizer_settings`, опции `b_option`), код модуля
`/bitrix/modules/ammina.optimizer/`, HTML страниц dmsnew.ru (локальная копия) и www.demis.ru.

## Что подключено

Ammina (настройки v5.1.0, лицензия до 22.11.2026) обрабатывает каждую страницу в `OnEndBufferContent`
(сортировка 1000): разбирает HTML в DOMDocument, оптимизирует и собирает обратно. Часть работы делает
удалённый сервер `srv01.opti-stack.ru`: сайт отправляет ему файлы, тот возвращает результат.

Профили настроек: «все сайты» → сайт `s1` → профили страниц (3 шт.: «TEST» для одной тестовой страницы,
«Новый дизайн» для `/services/kontekstnaja-reklama-redesign/` с выключенными CSS и JS, выключенный «Для
услуговых с новой структурой»). Около 30 адресов исключены целиком (в т. ч. все redesign-страницы,
`/company/`, `/contact/`), домены `crm.`, `double-d.`, `design-demis.ru` — тоже.

| Блок | Включено на s1 |
|---|---|
| Общее | выключено объединение CSS/JS ядром, JS переносится в конец body |
| CSS | объединение и минификация; **critical** (по всем классам страницы, ~100 классов панелей в исключениях, `MAX_CRITICAL_RECORD=5`); шрифты с `font-display: swap`; картинки в CSS → WebP; файлы `webfonts.min.css` и `styles.css` исключены (остаются блокирующими); `<style>` переносятся в конец body |
| JS | минификация (удалённо), объединение `keeporder`, **отложенный запуск** — `type="deferjs"` + свой загрузчик, скрипты стартуют по `load`/`pageshow`; исключены HeaderJilin и `inp.min.js` |
| Изображения | JPG q80 (Imagick), PNG (pngquant), **WebP** (cwebp, удалённо), `decoding="async"` |
| Lazyload | изображения с **blur-заглушкой** (генерирует удалённый сервер), теги img/div/a/li/span/tr/td, 6 классов-исключений; «antilazy» (снимает чужие lazy-классы и `data-src`) |
| Прочее | preconnect к 4 доменам; минификация HTML выключена |

Ещё: агенты `CheckCache`/`CheckImages`, обработчики `OnFileSave`/`OnAfterResizeImage` (предоптимизация
`/upload/iblock/`, `/upload/resize_cache/`), в `local/php_interface/include/agents.php` — свой агент, который
при недоступности сервера Ammina отключает оптимизацию на всём сайте.

## Critical CSS у Ammina

**Как работает.** Собираются все классы и id **всей страницы**, из них убираются классы из ручного списка
`IGNORE_CLASS` (~100 классов панелей, чтобы приблизиться к «первому экрану»), правило считается нужным,
если все классы и id его селектора есть в наборе. Critical вставляется в head, остальное — одним файлом
в конец body.

Проблемы:

1. **Это не первый экран.** Классы, не попавшие в список исключений, тянут свои стили со всей страницы:
   на главной 122 КБ инлайна (20 КБ gzip), в статьях — 144 КБ (47 КБ gzip). Каждая новая панель на сайте
   требует ручного добавления в `IGNORE_CLASS`.
2. **Чужой critical.** При `MAX_CRITICAL_RECORD=5`, когда для набора CSS уже есть 5 critical-файлов, новая
   страница получает critical **последней обработанной другой страницы** (`css.php`, `doMakeCriticalFile`).
   Если структура страниц отличается — первый экран рисуется без части стилей и прыгает после загрузки CSS.
3. **Ошибка разбора селекторов.** В `getAtomSelector()` вместо `mb_substr($s, $e + 1)` стоит
   `mb_strpos($s, $e + 1)`: всё, что идёт после первой скобки (`.a:not(.b) .c`), теряется, и такие правила
   проходят без проверки. Экранированные имена классов (`.uk-width-1-2\@m`) разбираются неверно, имена
   приводятся к нижнему регистру.
4. **Блокирующие стили остаются.** Исключённые `webfonts.min.css` и `styles.css` грузятся блокирующе в head,
   некритичный CSS — блокирующим `<link>` в конце body. На redesign-страницах (исключены из Ammina) —
   139 КБ инлайна плюс 178 КБ блокирующего CSS.

## Lazyload у Ammina

1. **Задерживает LCP.** Фон hero-блоков (`panel-hero-image`, `page-header-bg`, `top-site-image`) заменяется
   размытой заглушкой, настоящая картинка ставится только после `window.onload` — то есть после загрузки
   всех скриптов и картинок страницы. Это самый крупный элемент первого экрана.
2. Скрипт присваивает `window.onload = …` (затирает чужие обработчики), порог видимости 1% без запаса —
   картинки начинают грузиться, только когда уже на экране; контент, добавленный AJAX, не подхватывается.
3. В шаблоне у всех 72 картинок главной уже стоит `loading="lazy"`, включая первый экран, — Ammina это
   не исправляет. SVG получают `spacer.gif` вместо src: без JS их не видно.
4. Заглушки генерирует удалённый сервер; на локальной копии они не создаются.
5. Цена: из 0.35 с, которые Ammina добавляет к каждому некешированному запросу, 0.22 с — lazyload
   (XPath-поиск предков для каждого тега).

## Эксплуатация

- Зависимость от стороннего сервера: минификация JS, WebP, заглушки. При его недоступности агент сайта
  выключает оптимизацию целиком.
- Код модуля исправлен вручную (`// fix` в `lib/core2/parser/domparser.php`: исключения для Apple и
  HeaderJilin) — правки пропадут при обновлении.
- Вся страница проходит через DOMDocument и `saveHTML()`; отладочная статистика выводится в cp1251
  внутри UTF-8 страницы.
- +0.35 с к запросу при прогретом кеше, до 18–20 с при холодном.
- Кеш: 1.6 ГБ в `/bitrix/ammina.cache/` и 3.0 ГБ в `/upload/ammina.optimizer/`.
- Три уровня настроек с флагами наследования (~150 опций на профиль) и ~30 исключённых адресов.

## Что сделано в vspace.pagespeed (этап 1 — critical CSS)

- Первый экран определяется автоматически: шапка + первые N блоков (`.panel`, `.section`) с пределом по
  объёму, точная граница — маркером `<!--vps-fold-->`. Списка из 100 исключений нет.
- Содержимое скрытых при загрузке элементов (мега-меню, попап города, поиск, `.dropdown`) не тянет стили;
  cookie-баннер из футера и виджеты, которые строит JS, добавляются отдельно.
- Правило берётся, если выполним хотя бы один селектор из списка, и в вывод идут только выполнимые;
  селекторы разбираются с учётом `:not()`/`:is()`, атрибутов, экранирования; `:hover` и `@media print`
  не берутся; `@font-face` — только используемые.
- Свой кеш у каждой структуры страницы, без «чужого» critical; правка CSS пересобирает critical сама.
- HTML не пересобирается: правки вносятся точечно в исходную строку.
- Крупные `<style>` из head (главная, redesign) тоже уходят в critical + асинхронный файл.
- В head не остаётся блокирующих стилей: `preload` + `media="print"`/`onload` + `<noscript>`.
- CSS-блок Ammina на обработанных страницах выключается на лету; остальное у Ammina работает.

Critical — после удаления повторяющихся правил (наборы стилей страниц повторяют шапку из `main.min.css`).
Общий список `/articles/`: первый экран теперь заканчивается на первом ряду плиток, а не по пределу 40 КБ HTML, и
без повторов из `page-articles.min.css` critical уменьшился с 99 КБ (16.5 в gzip) до 56 КБ (9.8).

Визуальная проверка: скриншоты первого экрана 1440×900 и 390×844 в режиме «только critical»
(`?vps_critical=only`) против текущей страницы с Ammina. Услуги, статьи, контекст — совпадают попиксельно;
главная и redesign — отличия менее 2% (анимации и фон под полупрозрачным cookie-баннером, который в режиме
проверки не стилизован ниже первого экрана). Итоговая страница с модулем совпадает с текущей на 99–100%.

## Что осталось от Ammina и порядок замены

1. Lazyload изображений — сделать иначе: нативный `loading="lazy"` вне первого экрана, `fetchpriority` и
   preload для hero, без заглушек и без ожидания `onload`.
2. WebP — локальная конвертация (GD/Imagick), без внешнего сервера.
3. Отложенный JS (с сохранением порядка «сначала CSS, потом скрипты»), preconnect.
4. Отключить и удалить Ammina, убрать `Integration/AmminaBridge.php` и агент проверки её сервера.
